## Purpose

Run `beaver validate` before [`beaver plan`](/cli/plan) or [`beaver deploy`](/cli/deploy) to
catch configuration mistakes early. It parses and checks the current directory's
`.beaver/config.yml` — the file is not empty or oversized, it parses as YAML, it has no duplicate keys and no YAML anchors or
aliases (never allowed), `schema_version` is the supported version (`1`), and `project` is set — entirely on your machine. It does **not** check the values of the `deployment:` fields (strategy, replicas, resources, port, and so on) or reject keys it does not
know; for editor-side checking of those, use the schema from [`beaver config schema`](/cli/config), and see the
[`.beaver/config.yml` reference](/reference/deployment-specification).

## Syntax

```bash
beaver validate
```

Takes no arguments or flags.

## Consequences

Read-only: this never contacts the server and never touches the file. This is a fast, local
first check — an actual deploy still validates again server-side, so passing `validate`
locally doesn't guarantee a deploy will succeed, but it catches the common mistakes early.

## Examples

<Info>
  **Verified**: the commands on this page were executed against a live `beaver` build during this review; example output reflects what was actually returned (with real account/workspace values replaced by the fictional vocabulary).
</Info>

```bash
cd paperclip/
beaver validate
```

## Results & failures

| Situation | What you'll see | What to do |
| --- | --- | --- |
| Valid | No issues reported | Proceed to `beaver plan` or `beaver deploy`. |
| No config file | "No `.beaver/config.yml` in this directory." | Run `beaver config init` to create one. |
| Invalid | "Invalid `.beaver/config.yml`" with the specific problem | Fix the reported issue and re-run. |

<Note>
  `beaver config validate` is a separate command with the same purpose — checking your local
  `.beaver/config.yml` without deploying — reachable from the [`config`](/cli/config) family.
  The two aren't guaranteed to report identical diagnostics for every case; either is a
  reasonable first check.
</Note>

## Used in

- [`plan`](/cli/plan) and [`deploy`](/cli/deploy) — run `validate` first to catch mistakes
  locally.
