## What you'll build

A web app from your GitHub repository, deployed from the Dashboard onto a machine you own. The Dashboard handles the
deploy; **enrolling the machine and creating the cloud happen once in a terminal**, because the Dashboard cannot do those
two things.

## Before you start

- A **Linux machine you own** with Docker and Git (Ubuntu, Debian or Rocky Linux; amd64 or arm64).
- A **Docker Hub account** — Beaver tags the image it builds with your Docker Hub username.
- A **GitHub repository** with a `Dockerfile` at its root. The Builder machine clones it with its **own GitHub login** (`gh auth login` on that machine; check with `beaver git --auth`) — needed for a private repository. A Dockerfile is required —
  [what it must define](/deploy/dockerfile-requirements).
- A Beaver account. Sign up or sign in at [vectorihub.com](https://vectorihub.com) with Google, GitHub or email.

## Part 1 — once, in a terminal on the machine

Do steps 1–6 of the [CLI quickstart](/start/quickstart-cli): install the CLI, `beaver login`, `docker login`, `beaver connect`
(choose **Builder + Host**), then `beaver cloud create <name> --machines <machine-name>`. When you finish, the machine
appears under **Nodes** in the Dashboard and your cloud under **Clouds**.

## Part 2 — in the Dashboard

<Steps>
  <Step title="Let Beaver see your repositories">
    Open **Integrations** and connect GitHub. If you skip this, the repository list says *Beaver cannot see your
    repositories yet*. Connecting lets Beaver see the repositories you choose; signing in with GitHub alone does
    not ([why](/teams/signing-in-and-repository-access)).
  </Step>
  <Step title="Start a deployment">
    Pick the repository (and branch) you want to deploy from your projects/repositories view. Beaver opens the deployment form.
  </Step>
  <Step title="Choose where it builds and runs">
    Choose the **Builder** machine (the one you connected), then select the cloud under *Select where your application will be
    deployed*. If no builder or cloud is offered, return to Part 1 — a Builder has to be enrolled first.
  </Step>
  <Step title="Fill in the app details">
    Set the **Container Name** (the form tells you when the name is available), the port your app listens on (Beaver reads it
    from your Dockerfile through the selected Builder where it can), the **Deployment Path** if your Dockerfile is in a
    subfolder, your **DockerHub Username**, and the **Environment** — Production, Staging, Testing or Development. Add
    environment variables here if your app needs them ([how](/deploy/environment-variables)).
  </Step>
  <Step title="Deploy and watch">
    Submit the form. The deployment appears under **Deployments**; open it to follow the build and see its status.
  </Step>
</Steps>

<Tip>
The form's footer reminds you that the same thing is `beaver deploy` in a terminal — and a push to the connected branch triggers
later releases ([details](/cli/deploy)).
</Tip>

## Result

Your deployment shows a running status and a default address. Open the address in a browser. In the deployment's tabs you can
read logs, set environment variables and attach a domain.

## If it fails

- **No builder or cloud in the form** — finish Part 1 (the machine needs a role of Builder or Builder + Host, and a cloud must exist).
- **Container name is already taken** — choose another.
- **Repository list is empty** — reconnect GitHub under Integrations.
- More: [Troubleshooting](/operate/troubleshooting).
