**You are not allowed to do this**

The caller is signed in but not permitted to perform the operation. A response that can name the missing capability uses FORBIDDEN_CAPABILITY instead.

| | |
| --- | --- |
| Code | `FORBIDDEN` |
| Kind | Permission |
| HTTP status | `403` |
| CLI exit status | `1` |

## What to do

Ask an Owner or Admin of the workspace to do this or to change your role. If another workspace of yours has access, switch with `beaver workspace use`.

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "FORBIDDEN",
    "message": "You are not allowed to do this",
    "changed": false,
    "conditions": [],
    "repairs": [],
    "request_id": "req_…",
    "error": "You are not allowed to do this"
  }
}
```

Look it up offline with `beaver help FORBIDDEN`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
