**Beaver could not work out which workspace or project you mean**

No workspace, project or environment could be resolved from the flag, environment, config or default. The response shows each source consulted.

| | |
| --- | --- |
| Code | `CONTEXT_UNRESOLVED` |
| Kind | Invalid input |
| HTTP status | `400` |
| CLI exit status | `1` |

## What to do

The response names the flag or argument and shows an accepted value. Run `beaver help <command>` for the command's flags.

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "CONTEXT_UNRESOLVED",
    "message": "Beaver could not work out which workspace or project you mean",
    "changed": false,
    "conditions": [],
    "repairs": [],
    "request_id": "req_…",
    "error": "Beaver could not work out which workspace or project you mean"
  }
}
```

Look it up offline with `beaver help CONTEXT_UNRESOLVED`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
