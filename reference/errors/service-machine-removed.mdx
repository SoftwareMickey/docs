**The service's machine is no longer enrolled**

The machine the service ran on has been removed from the workspace, so Beaver can never reach its container or volume again. The service can be abandoned, which records that its data can no longer be managed.

| | |
| --- | --- |
| Code | `SERVICE_MACHINE_REMOVED` |
| Kind | Resource State |
| HTTP status | `409` |
| CLI exit status | `10` |

## What to do

The machine is no longer enrolled, so its data can no longer be reached. `beaver service delete NAME --abandon` removes the service from Beaver and asks you to type its name. See [A service's container went missing](/operate/service-container-missing#the-machine-is-gone-for-good).

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "SERVICE_MACHINE_REMOVED",
    "message": "The service's machine is no longer enrolled",
    "changed": false,
    "conditions": [],
    "repairs": [],
    "request_id": "req_…",
    "error": "The service's machine is no longer enrolled"
  }
}
```

Look it up offline with `beaver help SERVICE_MACHINE_REMOVED`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
