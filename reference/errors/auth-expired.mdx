**Your session has expired**

The session token is expired or was revoked. Sign in again, then retry.

| | |
| --- | --- |
| Code | `AUTH_EXPIRED` |
| Kind | Sign-in |
| HTTP status | `401` |
| CLI exit status | `1` |

## What to do

Sign in again with `beaver login`. In CI, set `BEAVER_TOKEN` and run `beaver login` once.

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "AUTH_EXPIRED",
    "message": "Your session has expired",
    "changed": false,
    "conditions": [
      {
        "id": "auth.session",
        "label": "Your session is valid",
        "status": "failed",
        "detail": "The session this machine holds is no longer accepted.",
        "expected": "an active session",
        "actual": "expired",
        "repair": {
          "kind": "command",
          "description": "Sign in again, then run the command again",
          "command": "beaver login"
        }
      }
    ],
    "repairs": [],
    "request_id": "req_41c9d7e2",
    "error": "Your session has expired"
  }
}
```

Look it up offline with `beaver help AUTH_EXPIRED`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
