**The server did not answer in time**

No response arrived before the deadline. A mutating request may have been applied anyway.

| | |
| --- | --- |
| Code | `NETWORK_TIMEOUT` |
| Kind | Temporary |
| HTTP status | `504` |
| CLI exit status | `1` |

## What to do

Read the conditions in the response: each says what was checked and how to fix it.

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "NETWORK_TIMEOUT",
    "message": "The server did not answer in time",
    "changed": false,
    "conditions": [],
    "repairs": [],
    "request_id": "req_…",
    "error": "The server did not answer in time"
  }
}
```

Look it up offline with `beaver help NETWORK_TIMEOUT`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
