**Beaver could not complete the operation**

An unexpected failure. Quote the request id when reporting it.

| | |
| --- | --- |
| Code | `INTERNAL` |
| Kind | Internal |
| HTTP status | `500` |
| CLI exit status | `1` |

## What to do

Beaver could not complete the operation. Quote the request id when you contact support: it identifies the exact failure.

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "INTERNAL",
    "message": "Beaver could not complete the operation",
    "changed": false,
    "conditions": [],
    "repairs": [],
    "request_id": "req_…",
    "error": "Beaver could not complete the operation"
  }
}
```

Look it up offline with `beaver help INTERNAL`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
