**A temporary condition blocked the request**

A transient condition (rate limit, maintenance, overload) blocked the request; retry later.

| | |
| --- | --- |
| Code | `TEMPORARY` |
| Kind | Temporary |
| HTTP status | `503` |
| CLI exit status | `1` |

## What to do

Read the conditions in the response: each says what was checked and how to fix it.

## What the response contains

Every failure — in the table output, `--json`, `--yaml` and the API — carries the same fields: `code`, `message`, `changed` (whether anything was altered), `conditions` (each requirement checked, with `status`, `detail` and a `repair`), `repairs`, a `retry` command and a `request_id`. Branch on `error.code`, never on the message text.

```json
{
  "ok": false,
  "error": {
    "code": "TEMPORARY",
    "message": "A temporary condition blocked the request",
    "changed": false,
    "conditions": [],
    "repairs": [],
    "request_id": "req_…",
    "error": "A temporary condition blocked the request"
  }
}
```

Look it up offline with `beaver help TEMPORARY`. See [Exit codes and output formats](/reference/exit-codes-and-output) for what a script can rely on.
