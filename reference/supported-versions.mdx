## Operating systems

| What | Supported |
| --- | --- |
| **Connected machines** (Builder and Host) | Linux: Ubuntu, Debian and Rocky Linux, on amd64 (x86_64) or arm64 (aarch64) |
| **Beaver CLI** on your computer | Linux, macOS and Windows. The Windows installer supports x86, amd64 and arm64 |
| **Dashboard** | The web app, in a current browser |
| **Beaver Desktop** | No public installer is published yet; see [Install Beaver Desktop](/install/desktop) |

A machine on another distribution may connect but `beaver connect` warns it is not supported ([Install the CLI](/install/cli#supported-environments)).

## Languages and frameworks

**Beaver deploys React applications, and refuses everything else.** Vite and Create React App both count as React; a meta-framework that depends on React — Next.js, Remix, Astro — does not, and is refused under its own name. [Bring your own app](/deploy/bring-your-own-app#what-counts-as-a-react-app) has the full table of what is detected and what deploys.

The refusal happens before anything is built, and it is enforced by the control plane rather than by the CLI, so it applies equally to the Dashboard, the CLI, a CI pipeline and a template deploy.

Your Dockerfile chooses its own versions — Beaver neither pins nor installs anything. The base images used by the sample Dockerfiles on that page are:

| Role | Image used in the samples |
| --- | --- |
| Build stage (bundling the app) | `node:22-alpine` |
| Static serving | `nginxinc/nginx-unprivileged:1.27-alpine` |
| Node serving | `node:22-alpine` |

Any other version works if your Dockerfile installs it.

## Where Beaver does not apply

- **Frameworks other than React.** Including Vue, Angular, Svelte, and Node backends such as Express or NestJS. See [Languages and frameworks](#languages-and-frameworks).
- **Other Git hosts.** Repository integration is GitHub only today ([Deploy from GitHub](/deploy/from-github)). A local project deploys from its GitHub remote.
- **Docker alternatives.** Deployments run as Docker containers.
