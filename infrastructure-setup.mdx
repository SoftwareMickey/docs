## Deploy Anywhere You Already Run

Beaver deploys to infrastructure you own — a cloud VM, a bare-metal box, or any Linux VPS. Preparing a machine follows the same shape everywhere: create it, open the right ports, install Beaver, and connect it.

## The Same Workflow, Every Provider

<Steps>
  <Step title="Create a machine">
    Provision a Linux server through your provider of choice.
  </Step>
  <Step title="Open the required ports">
    Allow SSH (22), and whichever of HTTP (80), HTTPS (443), or a custom app port your application needs.
  </Step>
  <Step title="Install Beaver">
    Follow [Install Beaver CLI on Linux](/installation), then run [`beaver doctor`](/beaver-doctor) to confirm the machine is ready.
  </Step>
  <Step title="Connect it">
    Run [`beaver connect`](/connect) and choose a [role](/machine-roles) for the machine.
  </Step>
</Steps>

<Note>
  You retain ownership and control of your own infrastructure — Beaver deploys onto machines you provision and manage, not onto Beaver-owned infrastructure.
</Note>

<Tip>Using a provider that isn't listed above? See [Custom VPS Providers](/infrastructure-setup/custom-vps-providers) — any Linux server with SSH, Docker, and internet access works the same way.</Tip>
