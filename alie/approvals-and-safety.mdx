Alie proposes actions with real effects. By default it **asks first**. An approval confirms **one specific proposed action**; it does not grant broader access.

## Decide what is waiting

<Tabs>
  <Tab title="Dashboard"><Note>Decide from Desktop or the CLI.</Note></Tab>
  <Tab title="Desktop">**Approvals** lists actions waiting for a decision, showing the exact operation, with **Approve** and **Reject** and an optional note. It shows the CLI equivalent for what you are deciding.</Tab>
  <Tab title="CLI">
    ```bash
    beaver alie approvals                  # every action waiting on confirmation, across the workspace
    beaver alie approve <approval-id>
    beaver alie reject <approval-id>
    ```
  </Tab>
</Tabs>

## Choose which tools need approval

Each tool falls back to a default approval mode derived from its risk. You can override one:

```bash
beaver alie approval-policies                         # per-tool overrides (says so if there are none)
beaver alie approval-policy set --tool <tool> --mode approval    # approval | auto
```

## Autopilot — how far it can act with no confirmation

<Warning>
Autopilot controls how far Alie can act with **no human confirmation at all**. Setting it above `off` is a consequential, **workspace-wide** change — confirm you mean it.
</Warning>

```bash
beaver alie autopilot                       # show the current level
beaver alie autopilot set --level safe      # off | safe | diagnostic | action | destructive
```

Each level permits everything the one before it does, plus more. Start at `off`.

## See what happened

```bash
beaver alie audit --limit 100               # Alie's tool and action audit trail
beaver alie audit --event-type <type>       # one event type
```
