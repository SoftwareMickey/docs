"GitHub" shows up in three different places in Beaver, and they are deliberately kept apart.
Most confusion about GitHub in Beaver comes from treating them as one thing.

| | What it answers | What you do | What it lets Beaver do |
| --- | --- | --- | --- |
| **Signing in with GitHub** | Who are you? | Choose *Continue with GitHub* on the sign-in page | Recognise you. Nothing else. |
| **Repository access** | Which repositories may Beaver read? | Install the Beaver GitHub App and pick repositories | Read and clone the repositories you selected, and hear about changes to them |
| **GitHub on your own machine** | Can *this computer* reach GitHub? | Sign in to the GitHub CLI locally | Nothing on Beaver's side — Beaver never sees it |

The rule that keeps this understandable: **signing in never gives Beaver access to your
repositories, and repository access never signs anyone in.** They start separately, succeed
or fail separately, and end separately.

## Signing in with GitHub

Choosing *Continue with GitHub* asks GitHub two things: who you are, and your email address.
That is all the permission requested. If you are new, an account is created for you; if you
have signed in this way before, you are signed back in to the same account.

Beaver keeps your GitHub user id, username, avatar and email address so it can recognise you
next time. It does **not** keep a GitHub access token — the short-lived token GitHub hands
over while you sign in is used once and discarded.

A few things worth knowing:

- **If your GitHub email is private,** the account is still created. It is given a
  placeholder address that cannot receive mail, so Beaver has no email to reach you on until
  you make one available.
- **If an account already uses your email,** Beaver will not merge the two automatically. You
  are asked to sign in the way you first created the account, then connect GitHub from your
  account settings. This is deliberate: an email address alone is not proof that two accounts
  belong to the same person.
- **If your account has two-factor authentication,** signing in with GitHub still asks for the
  second factor before a session begins.
- **You can connect GitHub to an existing account** from account settings, and remove it
  again — as long as you keep at least one other way to sign in.

## Connecting repositories

Repository access comes from the **Beaver GitHub App**. Installing it is a GitHub-side
decision: GitHub shows you the account you are installing it on and lets you choose *all
repositories* or only the ones you name. Beaver can read only what you selected there.

When you finish, Beaver asks GitHub to confirm that **your** GitHub account really has access
to that installation. Only then is it connected. This is what stops one person from claiming
another person's or organisation's installation just by knowing its number.

What that means in practice:

- **Personal accounts:** you can connect the installation on your own GitHub account.
- **Organisations:** any member who can access the installation can connect it. Each Beaver
  user who connects the same organisation gets their own connection; nobody takes over
  anyone else's.
- **Organisations that require approval:** if you are not an owner, GitHub sends the owner a
  request instead of installing. Beaver shows *Installation requested*; once an owner
  approves, connect again.
- **Nothing is ever connected without that confirmation.** If GitHub cannot confirm it, the
  attempt ends as *denied* and nothing is saved.

Beaver stores which installation you connected, the account it belongs to and how repositories
were selected. It does not store a token for it; access is granted to Beaver on demand for as
long as the installation stands.

## Common questions

<AccordionGroup>
  <Accordion title="I signed in with GitHub — why can't Beaver see my repositories?">
    Signing in only proves who you are. Repository access is a separate step: install the
    Beaver GitHub App and choose repositories. New GitHub sign-ups are offered this step right
    after their account is created, and it can be skipped and done later.
  </Accordion>
  <Accordion title="I uninstalled the GitHub App — am I signed out?">
    No. Your session and your ability to sign in are unchanged. Beaver notices the
    uninstall, marks that connection as disconnected, and projects that used it can no longer
    pull new commits until you connect again.
  </Accordion>
  <Accordion title="I removed GitHub as a sign-in method — did my repositories disconnect?">
    No. Removing GitHub as a way to sign in leaves your repository connections exactly as
    they were, and signing out does too. Beaver will not let you remove your only way to sign
    in.
  </Accordion>
  <Accordion title="Which GitHub does my build machine use?">
    Neither of the above. A machine that builds your code uses the GitHub sign-in on that
    machine itself, which Beaver never sees and never stores. Checking it is a separate,
    local step from signing in to Beaver or connecting repositories.
  </Accordion>
  <Accordion title="Someone removed a repository from the app — what happens?">
    Beaver is told by GitHub and updates what it can see. Projects linked to a repository that
    is no longer selected stop pulling new commits; select the repository again in GitHub's
    settings for the app to restore it.
  </Accordion>
</AccordionGroup>

## The words you will see

Finishing a connection always ends in one of these, in the web app, the desktop app and the
command line alike.

| Result | Meaning |
| --- | --- |
| **Connected** | GitHub confirmed your access and the repositories you selected are available. |
| **Requested** | An organisation owner must approve the app. Nothing is connected yet. |
| **Cancelled** | You backed out on GitHub. No access was granted. |
| **Denied** | GitHub did not confirm your account has access to that installation. Nothing was saved. |
| **Expired** | The link only works once, in the browser that started it. Start again. |
| **Failed** | GitHub returned an error while finishing. Nothing was saved; try again. |

Each has a remedy in [Troubleshooting GitHub](/guides/troubleshooting-github).
