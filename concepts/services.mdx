A **service** is a managed backing component — a database, cache, or similar dependency —
that you attach to your application instead of running and maintaining yourself.

```bash
beaver service create paperclip-db --type postgres
beaver service attach paperclip-web --database paperclip-db
```

## What attaching one actually does

`paperclip-web` needs a Postgres database. Instead of running Postgres on the same machine
and managing its backups and upgrades by hand, you provision a service (`paperclip-db`) and
attach it. Your application receives a connection string as an environment variable, using a
prefix you choose, and can use it once the attachment takes effect — for most services,
that's your next deployment.

## What you can see and control

You can resize a service's resources, upgrade its version, and detach it later. Detaching
removes the injected variable but does **not** delete the underlying database — only
deleting the service itself does that.

<Warning>
  Deleting a service permanently removes its data. Detaching an application from a service
  does not delete the service — delete it separately if that's actually what you want.
</Warning>

Some service types don't support in-place version upgrades and require provisioning a new
service and migrating data across.

## Private vs shared data

By default, attaching a new application gives it a brand-new, private slice of the service —
its own database, key space, bucket, or equivalent, depending on the service type — that no
other application can read or write. If you want two applications to work on the same data (an
API and its background worker, say), you connect the second one to the first's existing
resource instead and confirm you want to share it. Beaver never puts two applications on the
same data unless you say so explicitly.

## Each app has its own login

Every application you attach to a service gets its own credential, scoped to only the data it's
connected to — never a login shared with any other application, even one attached to the same
underlying resource. Disconnecting an application revokes only its own credential; the
resource and every other connected application are untouched. This is why detaching never
deletes your data: it only removes the one login that no longer needs to exist.
