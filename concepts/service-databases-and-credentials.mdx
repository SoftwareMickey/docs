Inside one service (say, a Postgres instance), you can have multiple **logical databases** —
one per application that uses it, so each application's data stays isolated even when
sharing the underlying service.

```bash
beaver service reveal paperclip-db
```

## Why share one service instead of running several

Two applications both needing Postgres doesn't mean you need two separate service instances
to manage, back up, and pay for. A logical database per application gets you isolation
without the operational overhead of running more services than you need.

## What you can see and control

Connection details (host, port, database name) are shown by default; the actual credential
value stays hidden until you explicitly reveal it, which asks for confirmation first.
Rotating a credential issues a new value and invalidates the old one — any connection still
using the old value stops working and needs to reconnect with the new one.

## Detach versus revoke — not the same thing

**Detaching** an application from a service removes its injected connection variable but
leaves the database and its data untouched. **Revoking** access is more targeted — it
invalidates that specific credential without necessarily detaching the application's
configuration. Know which one you actually want before reassigning a database to a
different application.

<Warning>
  Rotating a credential is not reversible — the old value cannot be recovered once replaced.
  Update every place that used it before, or immediately after, rotating.
</Warning>
