# Install Beaver CLI on Linux

This guide takes a fresh Linux server from nothing to a connected Beaver machine: install the CLI, verify it, log in, and connect.

## Supported environments

<Columns>
  <Column>
    <Check>Ubuntu</Check>
    <Check>Debian</Check>
    <Check>Rocky Linux</Check>
  </Column>
  <Column>
    <Check>amd64 (x86_64)</Check>
    <Check>arm64 (aarch64)</Check>
  </Column>
</Columns>

<Note>
  Installing on macOS or Windows? See the [full CLI reference](/cli#installing-the-cli) for those platforms.
</Note>

---

<Steps>
  <Step title="Install the CLI">
    Run the install script. It detects your OS and architecture and installs `beaver` to `/usr/local/bin`:

    ```bash
    curl -fsSL https://cli.vectorihub.com/install.sh | sh
    ```

    <Tip>
      No permission to write to `/usr/local/bin`? Set `INSTALL_DIR` to install somewhere else, such as a directory in your own home folder:

      ```bash
      curl -fsSL https://cli.vectorihub.com/install.sh | INSTALL_DIR=$HOME/.local/bin sh
      ```

      Make sure that directory is on your `PATH`.
    </Tip>
  </Step>

  <Step title="Verify the installation">
    Confirm `beaver` is installed and check the version:

    ```bash
    beaver version
    ```

    ```txt Example output
    🐹 VectorIHub CLI v0.1.3 (a1b2c3d)
    ```

    If you see a version number, the install worked. If you see `command not found`, see [Common installation problems](#common-installation-problems) below.
  </Step>

  <Step title="Run beaver doctor">
    Before doing anything else, confirm your environment is ready:

    ```bash
    beaver doctor
    ```

    <Warning>
      Run this **before** logging in or connecting your machine. It catches missing requirements early instead of surfacing them partway through `connect` or a deployment. See the full [Beaver Doctor guide](/beaver-doctor) for what it checks and how to fix what it finds.
    </Warning>
  </Step>

  <Step title="Log in">
    Start the interactive shell and log in to your Beaver account:

    ```bash
    beaver
    ```

    At the `beaver ▸` prompt, type:

    ```txt
    login
    ```

    You'll be prompted for your email and password:

    ```txt
    beaver ▸ login
    Email: you@example.com
    Password:
    Login successful!

      Account     yourname
      Workspace   yourname's workspace
    ```
  </Step>

  <Step title="Connect your machine">
    Still at the `beaver ▸` prompt, connect this machine to your workspace:

    ```txt
    connect
    ```

    `connect` checks the machine over, then asks which role you want it to fill.

    <Info>
      Not sure whether to pick Builder, Host, or Builder + Host? [Choose Your Beaver Setup](/choose-your-setup) answers that in under 2 minutes. For the full `connect` walkthrough — prerequisites, verification, and troubleshooting — see the [`beaver connect` guide](/connect).
    </Info>

    Once connected, this machine shows up in `server --list` and in the dashboard, ready to build and/or run your applications.
  </Step>
</Steps>

## Common installation problems

<Tip>
  Once `beaver` is installed, [`beaver doctor`](/beaver-doctor) can check the rest of your setup automatically and suggest fixes.
</Tip>

<AccordionGroup>
  <Accordion title="beaver: command not found">
    The install script installs to `/usr/local/bin` by default, which is on most systems' `PATH`. If you set a custom `INSTALL_DIR`, make sure that directory is on your `PATH`:

    ```bash
    export PATH="$HOME/.local/bin:$PATH"
    ```

    Add this line to your shell profile (`~/.bashrc`, `~/.zshrc`, etc.) to make it permanent, then open a new shell.
  </Accordion>

  <Accordion title="Permission denied while installing">
    If the install script can't write to `/usr/local/bin`, either run it with `sudo`:

    ```bash
    curl -fsSL https://cli.vectorihub.com/install.sh | sudo sh
    ```

    or install to a directory you own with `INSTALL_DIR` (see [Install the CLI](#install-the-cli) above).
  </Accordion>

  <Accordion title="Unsupported OS or architecture">
    `beaver` supports Ubuntu, Debian, and Rocky Linux on amd64 or arm64. If your server runs a different distribution, `connect` may still warn you that the machine isn't supported — check [Supported environments](#supported-environments) above before provisioning a server.
  </Accordion>

  <Accordion title="login or connect says 'only available inside the interactive shell'">
    `login` and `connect` are shell-only commands. Run `beaver` by itself first to open the interactive shell, then type `login` or `connect` at the `beaver ▸` prompt — don't pass them as arguments directly from your OS shell.
  </Accordion>

  <Accordion title="connect can't reach the internet">
    Your machine needs outbound internet access to connect to Beaver. Check that the machine has a working connection and that no firewall is blocking outbound traffic, then try `connect` again. See the [`beaver connect` troubleshooting section](/connect#troubleshooting) for more.
  </Accordion>
</AccordionGroup>
