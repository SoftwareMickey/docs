### What needs a fresh confirmation

These actions require a fresh confirmation at the moment you do them — a code from your authenticator app, a passkey or security key, or a recovery code — even if you are already signed in. The confirmation works once, for that one action, and expires after ten minutes.

| Action | Where | Confirmation |
| --- | --- | --- |
| Approving a new CLI or Desktop sign-in (a 30-day credential) | The browser approval page | `device_approve:<pairing code>` |
| Replacing the authenticator app | Settings → Security | `mfa_replace` |
| Turning 2-step verification off | Settings → Security | `mfa_disable` |
| Generating a new set of recovery codes | Settings → Security | `mfa_recovery_regenerate` |
| Adding a passkey or security key | Settings → Security | `mfa_passkey_add` |
| Removing one passkey, security key or authenticator app while others remain | Settings → Security | `mfa_factor_remove` |

No other action asks for a fresh confirmation today.

### Error reasons

| Reason | What it means |
| --- | --- |
| `invalid_code` | The code was not accepted. A code that was already used looks exactly the same, on purpose. |
| `code_required` | Nothing was entered. |
| `mfa_not_enabled` | The account has no 2-step verification to use. |
| `mfa_locked` | Too many wrong authenticator codes; codes are paused for a short time (see Retry-After). |
| `recovery_locked` | Too many wrong recovery codes; recovery codes are paused for a while (see Retry-After). |
| `rate_limited` | A request limit was reached; try again later. |
| `passkey_failed` | The passkey or security key was not accepted (wrong site, wrong key, expired or already used). Nothing about which is shown. |
| `webauthn_unavailable` | Passkeys are not available on this deployment yet; use the authenticator app or a recovery code. |
| `passkey_limit` | The account already holds the maximum number of passkeys. |
| `passkey_duplicate` | That passkey is already registered on this account. |
| `challenge_not_found` | The sign-in expired, was already used or was cancelled; sign in again. |
| `challenge_exhausted` | The sign-in used up its attempts; sign in again. |
| `enrollment_expired` | The set-up expired or ran out of attempts; start again. |
| `endpoint_moved` | An out-of-date client called an endpoint that has been replaced. |
| `step_up_required` | A sensitive action needs a fresh confirmation with the second factor. |
| `invalid_scope` | A confirmation was requested for an action that does not exist. |
| `recovery_link_invalid` | An emailed recovery link was already used, has expired, or was never issued. |
| `policy_mfa_required` | A workspace the person belongs to requires 2-step verification before a CLI or Desktop sign-in can be approved. |
| `policy_passkey_required` | A workspace the person belongs to requires a passkey or security key; a CLI or Desktop sign-in must be approved with one. |
| `mfa_use_device_login` | The CLI's direct password sign-in is closed to accounts with 2-step verification; use the browser sign-in. |
| `MFA_PASSKEY_REQUIRED` | A workspace requires a passkey or security key and this session did not sign in with one; sign in again with the passkey. |
| `MFA_REQUIRED` | A workspace requires 2-step verification and the person has not turned it on (after any grace period). |

### Notifications

Every one of these is mandatory: it cannot be muted, and it is sent to the account's inbox and email.

| Notification | When it is sent |
| --- | --- |
| `identity.mfa_admin_reset` | Support reset 2-step verification; all sessions were signed out. |
| `identity.mfa_disabled` | 2-step verification was turned off. |
| `identity.mfa_enabled` | 2-step verification was turned on. |
| `identity.mfa_factor_removed` | One passkey, security key or authenticator app was removed (others remain); other sessions were signed out. |
| `identity.mfa_locked` | Too many wrong codes locked authenticator guessing for a while. |
| `identity.mfa_passkey_added` | A passkey or security key was added. |
| `identity.mfa_recovered` | A recovery code was used to sign in. |
| `identity.mfa_recovery_cancelled` | A scheduled removal was cancelled. |
| `identity.mfa_recovery_codes_regenerated` | A new set of recovery codes was generated; the old set stopped working. |
| `identity.mfa_recovery_executed` | 2-step verification was removed after the recovery wait; all sessions were signed out. |
| `identity.mfa_recovery_requested` | A removal of 2-step verification is scheduled (after the email-recovery link or a support reset was approved); it can be cancelled. |
| `identity.mfa_replaced` | The authenticator app was replaced; other sessions were signed out. |
| `workspace.mfa_enforcement_blocked` | The deadline passed and the member is blocked until they turn it on (sent once). |
| `workspace.mfa_enforcement_enabled` | A workspace now requires 2-step verification (to members without it, with their deadline). |
| `workspace.mfa_enforcement_reminder` | A reminder before the deadline (3 days and 1 day), or one the owner sent. |
| `workspace.mfa_readiness_digest` | To owners, weekly while members still lack 2-step verification. |
| `workspace.mfa_recovery_started` | To owners: a member of an enforcing workspace started 2-step verification recovery. |
