› what should be the guide when implementing the documentation writing??


• The guide should be: document the complete user-facing contract of the CLI, while keeping implementation details private.

  Use these rules when writing:

  1. Verify before describing. Check registered commands, flags, and their implementation. Help text is a starting point; examples and claimed behavior must match the
     code.

  2. Cover every command and flag. Maintain a coverage inventory so nothing disappears between the CLI and docs. Include flag aliases, accepted values, defaults,
     requirements, conflicts, and interactions.

  3. Explain purpose before syntax. Start with the problem the command solves and when someone should use it, then show the simplest useful example.
  4. Make consequences explicit. Explain what changes, whether it affects a running application, whether a redeploy is required, and what happens on failure or timeout.
  5. Write examples users can adapt. Use consistent fictional projects and services. Show common workflows and meaningful flag combinations. Keep credentials and real
     infrastructure identifiers out.

  6. Describe observable behavior. Explain inputs, outputs, limitations, and recovery steps. Keep database schemas, private endpoints, routing algorithms, orchestration
     mechanisms, and internal design decisions in private engineering docs.

  7. Separate reference from workflows. Command reference pages explain every option. Task guides connect commands into a complete outcome. Link between them.
  8. Explain shared flags once, with local context. Give global flags a central reference, but explain special behavior on each affected command page.
  9. Validate the finished docs. Check navigation, links, syntax, examples, and coverage. Distinguish verified command execution from examples reviewed against code.
  10. Keep docs part of future changes. Adding or changing a command, flag, default, or output should trigger a documentation review.

  For every page, the final review should ask: Can a user complete the task and understand its consequences—and does every technical detail included help them do that?
