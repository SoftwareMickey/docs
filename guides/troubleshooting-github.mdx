New to how the pieces fit? [Signing in vs. connecting repositories](/concepts/signing-in-and-repository-access)
explains the difference between proving who you are and granting repository access — most
problems below come down to which of the two is affected.

Find the message you saw. The headings use the same wording the web app, desktop app and
command line show.

## Signing in with GitHub

### This email already has a Beaver account

An account already uses the email on your GitHub profile. Beaver never merges accounts
automatically, because an email address alone doesn't prove both accounts are yours.

1. Sign in the way you first created the account (email and password, or another provider).
2. Open your account settings and connect GitHub from there.

### Sign-in cancelled

You pressed Cancel on GitHub. Nothing was changed. Start again whenever you like.

### That sign-in link expired

Sign-in links work once, only in the browser that started them, and only for a few minutes.
This happens when you press Back after signing in, open the link in a different browser, or
wait too long on GitHub's page. Start the sign-in again from the beginning.

<Tip>
  If it keeps happening in a single browser, make sure that browser accepts cookies for the
  Beaver site and isn't blocking them for this tab.
</Tip>

### That account is already connected elsewhere

The GitHub account you chose is linked to a different Beaver account. Sign in to that
account instead, or connect a different GitHub account here.

### The provider reported a problem

GitHub couldn't complete the sign-in. Try again in a moment; if GitHub itself is having
problems, wait for it to recover.

### Sign in first

Connecting a sign-in method to an existing account needs an active session. Sign in, then
connect it from your account settings.

### Sign in again to make this change

Your account has two-factor authentication, so changing sign-in methods needs a recent
sign-in. Sign in again, complete the second step, and repeat the change.

### This sign-in method is unavailable

Sign-in with GitHub is temporarily off for this deployment. Use another way to sign in, or
try again later. If you run the deployment yourself, see
[Checking the configuration](#checking-the-configuration).

### Sign-in could not be completed

Something went wrong finishing the sign-in and nothing was changed. Try again. If it repeats,
[report it](#still-stuck) with the time it happened.

## Connecting repositories

### Installation requested

You aren't an owner of that GitHub organisation, so GitHub sent the owner a request instead of
installing the app. Nothing is connected yet.

1. Ask an owner of the organisation to open the pending request in the organisation's GitHub
   settings under *GitHub Apps* and approve it.
2. Once approved, connect the organisation again from Beaver.

### GitHub connection cancelled

You backed out on GitHub. No repository access was granted. Connect again when ready.

### That GitHub installation could not be connected

GitHub didn't confirm that **your** GitHub account has access to that installation, so
nothing was saved. This protects installations from being claimed by anyone who happens to
know their number.

- Check which GitHub account your browser is signed in to. If it's the wrong one, sign out of
  GitHub, sign in to the right account, and connect again.
- For an organisation, you must be a member who can see the installation. Ask an owner to
  add you or to install it themselves.
- A **personal** installation can only be connected by the GitHub user it belongs to.

### That connection attempt expired

The connection link works once, in the browser that started it, for a few minutes. Start
again from the same browser, and finish the GitHub step without leaving the page open for
long.

### GitHub could not be connected

GitHub returned an error while finishing the connection, so nothing was saved. Try again. If
it repeats, GitHub may be having an incident; wait and retry.

## After it was working

### I changed repository access on GitHub

If you use **Configure** on GitHub to add or remove repositories, GitHub sends you back to
Beaver and the change shows up straight away. This only works for an installation you already
connected from your own Beaver account, in the browser where you're signed in to Beaver. If you
land on "expired" instead, sign in to Beaver in that browser and try Configure again, or
reconnect from **Integrations → GitHub**.

### Connection suspended

*"The GitHub App installation is suspended."* An owner of the GitHub account or organisation
suspended the app. Ask them to unsuspend it in GitHub's settings. Your sign-in is unaffected;
projects that use that connection can't pull new commits until it's unsuspended.

### Connection disconnected

*"The GitHub App was uninstalled or lost access."* The app was removed from that account or
organisation on GitHub. Reconnect it from Beaver to restore repository access. Your sign-in is
unaffected.

### A repository is missing

Beaver can only see the repositories selected for the app. If a repository you expect isn't
listed, or a project stopped pulling commits from it, open the app's settings on GitHub and
add the repository to the selection. Changes there are picked up by Beaver automatically.

## From the command line

`beaver github install` exits with a code you can branch on in scripts:

| Exit code | Result | Meaning |
| --- | --- | --- |
| `0` | connected, or requested | Done — or an organisation owner has been asked to approve. |
| `3` | cancelled | You backed out on GitHub. |
| `4` | denied | GitHub didn't confirm your access. Nothing saved. |
| `5` | failed | GitHub returned an error. Nothing saved. |
| `6` | expired | The connection attempt expired. Run it again. |
| `7` | timeout | Gave up waiting. If you finished in the browser, run `beaver github` to check. |

Over SSH or in CI, pass `--no-browser` to print the URL instead of opening a browser. See
[`beaver github`](/cli/github) and [`beaver login`](/cli/login).

<Note>
  `beaver git --auth` is a different thing: it checks the GitHub CLI login on the machine
  you run it on. It has no effect on your Beaver sign-in or on which repositories Beaver can
  read.
</Note>

## Checking the configuration

If you operate your own Beaver deployment and GitHub sign-in or installation misbehaves for
everyone, the cause is nearly always configuration: a callback URL that differs by a single
character, a missing secret, or the app and the site living on unrelated domains. The
platform can check its own setup and list the exact URLs to compare with your GitHub App's
settings — ask your platform administrator to run the GitHub configuration check.

## Still stuck?

Contact support with the time the problem happened and the wording of the message you saw.
You never need to send a password, a token or a key, and support will never ask for one.
