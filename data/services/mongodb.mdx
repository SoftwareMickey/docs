MongoDB is a document database — a common choice when your data doesn't fit neatly into
relational tables, or your stack is already built around a document model.

## At a glance

| | |
| --- | --- |
| Type | `mongodb` — `beaver service create <name> --type mongodb` |
| Versions | 6.0, 7.0 (default), 8.0 — confirm with `beaver service catalog` |
| Default size | 1 CPU · 1024 MB memory · 20 GB storage — change with `beaver service resize` |
| Default port | 27017 (on the service's private address; never published publicly) |
| Persistence | A data volume is always provisioned |
| Isolated resource per application | database — each attached app gets its own, with its own credential |
| Variables injected on attach | `DATABASE_URL`, `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD` (prefix changeable with `--env-prefix`) |

## Add it

```bash
beaver service create paperclip-db --type mongodb
```

## Attach it

```bash
beaver service attach paperclip-db --container paperclip-web --env-prefix MONGO
```

Your application receives a connection string as an environment variable using the prefix
you choose. It's usable once the attachment takes effect — for most services, that's your
next deployment.

## Manage it

```bash
beaver service reveal paperclip-db
beaver service backup paperclip-db
beaver service resize paperclip-db --cpu 2 --memory 2048
```

See [Service databases and credentials](/data/credentials-and-connection-strings) for
reveal/rotate/detach behavior, and [Backups and restoration](/data/backups-and-restore)
for scheduling and restoring.

## Connect from your application

[Attach the service](/start/first-service) to your application, then redeploy so the injected variables reach the container. Your app reads the connection from the environment.

<CodeGroup>
```js Node.js
import { MongoClient } from "mongodb";
const client = new MongoClient(process.env.DATABASE_URL);
await client.connect();
console.log(await client.db().command({ ping: 1 }));
```
```python Python
import os
from pymongo import MongoClient
print(MongoClient(os.environ["DATABASE_URL"]).admin.command("ping"))
```
</CodeGroup>

<Note>These snippets are illustrative; check your driver's documentation for options such as TLS and pooling.</Note>

## Verify, back up and troubleshoot

- **Healthy?** `beaver service show <name>` shows status, placement and attached applications. An unhealthy service: `beaver service retry <name>`.
- **From your laptop:** `beaver service connect <name> --local-port 27017` opens a tunnel on `127.0.0.1` ([Connect locally](/data/connect-locally)).
- **Back up:** `beaver service backup <name>` takes a manual backup; see [Backups and restore](/data/backups-and-restore) for schedules, destinations and restore.
- **Credentials:** `beaver service reveal <name>` prints the live connection string and records an audit event; rotate one database's credential with `beaver service database rotate <db-name> <service>`.
- **Detach vs delete:** detaching an app ends only its own access. `beaver service delete` keeps the data volume; `beaver service delete-volume` destroys it permanently.
