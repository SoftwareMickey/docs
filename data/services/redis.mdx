Redis is an in-memory cache and data store — commonly used for caching, session storage,
queues, and rate limiting.

## At a glance

| | |
| --- | --- |
| Type | `redis` — `beaver service create <name> --type redis` |
| Versions | 6, 7 (default) — confirm with `beaver service catalog` |
| Default size | 0.5 CPU · 512 MB memory · 5 GB storage — change with `beaver service resize` |
| Default port | 6379 (on the service's private address; never published publicly) |
| Persistence | Optional — `--no-persistence` gives a cache-style service with no data volume |
| Isolated resource per application | key space (numbered 0–15, so up to 16 per service) — each attached app gets its own, with its own credential |
| Variables injected on attach | `REDIS_URL`, `REDIS_HOST`, `REDIS_PORT`, `REDIS_NAME`, `REDIS_USER`, `REDIS_PASSWORD` (prefix changeable with `--env-prefix`) |

## Add it

```bash
beaver service create paperclip-cache --type redis
```

## Attach it

```bash
beaver service attach paperclip-cache --container paperclip-web --env-prefix REDIS
```

Your application receives a connection string as an environment variable using the prefix
you choose. It's usable once the attachment takes effect — for most services, that's your
next deployment.

## Manage it

```bash
beaver service reveal paperclip-cache
beaver service resize paperclip-cache --cpu 1 --memory 512
```

## Higher availability

For workloads that need more than a single instance, Redis is also available as a
**cluster** or **sentinel** deployment, provisioned the same way as any other cluster:

```bash
beaver service cluster create paperclip-cache --type redis-cluster --replicas 3
```

See [Service clusters](/data/high-availability) for when a cluster is worth the extra
members, and member health/resizing/replacement once you have one.

## Connect from your application

[Attach the service](/start/first-service) to your application, then redeploy so the injected variables reach the container. Your app reads the connection from the environment.

<CodeGroup>
```js Node.js
import Redis from "ioredis";
const redis = new Redis(process.env.REDIS_URL);
await redis.set("hello", "beaver");
console.log(await redis.get("hello"));
```
```python Python
import os, redis
r = redis.Redis.from_url(os.environ["REDIS_URL"])
r.set("hello", "beaver"); print(r.get("hello"))
```
</CodeGroup>

<Note>These snippets are illustrative; check your driver's documentation for options such as TLS and pooling.</Note>

## Verify, back up and troubleshoot

- **Healthy?** `beaver service show <name>` shows status, placement and attached applications. An unhealthy service: `beaver service retry <name>`.
- **From your laptop:** `beaver service connect <name> --local-port 6379` opens a tunnel on `127.0.0.1` ([Connect locally](/data/connect-locally)).
- **Back up:** `beaver service backup <name>` takes a manual backup; see [Backups and restore](/data/backups-and-restore) for schedules, destinations and restore.
- **Credentials:** `beaver service reveal <name>` prints the live connection string and records an audit event; rotate one database's credential with `beaver service database rotate <db-name> <service>`.
- **Detach vs delete:** detaching an app ends only its own access. `beaver service delete` keeps the data volume; `beaver service delete-volume` destroys it permanently.
