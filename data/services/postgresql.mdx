PostgreSQL is the default relational database for most Beaver projects — a general-purpose
SQL database with strong support for structured data, transactions, and extensions.

## Add it

```bash
beaver service create paperclip-db --type postgres
```

Omit `--version` to use the default, or pin one explicitly:

```bash
beaver service create paperclip-db --type postgres --version 17
```

## Flavors

PostgreSQL comes in flavors for common workloads. Each is the same managed database — the same
credentials, attach, backups, and health checks — with an extension already enabled in every
database, and each has its own release you can pin with `--distribution-version`.

## Versions and upgrades

PostgreSQL 14, 15, 16 (default), 17 and 18 are supported. `beaver service show` lists the
PostgreSQL version and, for a flavor, the extension release as separate fields.

A major version upgrade is never done in place: Beaver backs the service up, restores it into a
new server on the newer version, checks it, and only then switches over, leaving the original
data untouched. Upgrades are forward only, skipping a major version needs explicit
confirmation, and a downgrade is refused. Starting an upgrade is not yet available from the CLI
or the desktop app.

## Health

Besides checking that the database answers, Beaver periodically writes and reads a row to prove
the data path works. A service that is running but fails that check — for example one that has
gone read-only — is shown as **degraded** rather than healthy, and returns to healthy once the
check passes. Nothing is restarted for you. See [Services](/data/services-and-persistence#health).

## Attach it

```bash
beaver service attach paperclip-db --container paperclip-web --env-prefix DATABASE
```

Your application receives a connection string as an environment variable using the prefix
you choose (`DATABASE_URL` above). It's usable once the attachment takes effect — for most
services, that's your next deployment.

### If an attach doesn't finish

Granting your application access to its database and writing the `DATABASE_*` variables
are separate steps. If one fails, the attachment is kept but marked `access_pending`
in `beaver service show`, and a deploy is blocked with
`Attached service environment is incomplete`. The error includes the database's own
message (credentials are never included).

Fix the cause and run the same `beaver service attach` command again. It resumes
where it stopped, rewrites all six managed variables (`DATABASE_URL`, `DATABASE_HOST`,
`DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD`), and the
attachment returns to `ready`. Variables you set yourself with the same name are left alone.

### Database names

Names use lowercase letters, numbers and underscores, start with a letter, and can be up to
57 characters. An application attached as read-only can query the database but can't create or
change anything in it.

## Manage it

```bash
beaver service reveal paperclip-db
beaver service backup paperclip-db
beaver service resize paperclip-db --cpu 2 --memory 2048
```

See [Service databases and credentials](/data/credentials-and-connection-strings) for
reveal/rotate/detach behavior, and [Backups and restoration](/data/backups-and-restore)
for scheduling and restoring.

## Connect from your application

[Attach the service](/start/first-service) to your application, then redeploy so the injected variables reach the container. Your app reads the connection from the environment.

<CodeGroup>
```js Node.js
import pg from "pg";
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
const { rows } = await pool.query("select 1 as ok");
```
```python Python
import os, psycopg
with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
    print(conn.execute("select 1").fetchone())
```
</CodeGroup>

<Note>These snippets are illustrative; check your driver's documentation for options such as TLS and pooling.</Note>

## Verify, back up and troubleshoot

- **Healthy?** `beaver service show <name>` shows status, placement and attached applications. An unhealthy service: `beaver service retry <name>`.
- **From your laptop:** `beaver service connect <name> --local-port 5432` opens a tunnel on `127.0.0.1` ([Connect locally](/data/connect-locally)).
- **Back up:** `beaver service backup <name>` takes a manual backup; see [Backups and restore](/data/backups-and-restore) for schedules, destinations and restore.
- **Credentials:** `beaver service reveal <name>` prints the live connection string and records an audit event; rotate one database's credential with `beaver service database rotate <db-name> <service>`.
- **Detach vs delete:** detaching an app ends only its own access. `beaver service delete` keeps the data volume; `beaver service delete-volume` destroys it permanently.
