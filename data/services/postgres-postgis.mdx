PostGIS is a [PostgreSQL](/data/services/postgresql) flavor: the same managed database, backups,
credentials, and attach workflow, with the PostGIS geometry and geography types and spatial
functions already available.

## At a glance

| | |
| --- | --- |
| Type | `postgis` — `beaver service create <name> --type postgis` |
| Versions | PostgreSQL 14–18 (default 17); PostGIS 3.4, 3.5 (default) — confirm with `beaver service catalog` |
| Default size | 1 CPU · 1536 MB memory · 20 GB storage — change with `beaver service resize` |
| Default port | 5432 (on the service's private address; never published publicly) |
| Persistence | A data volume is always provisioned |
| Isolated resource per application | database — each attached app gets its own, with its own credential |
| Variables injected on attach | `DATABASE_URL`, `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USER`, `DATABASE_PASSWORD` (prefix changeable with `--env-prefix`) |
| Release flag | `--distribution-version` pins the postgis release (the PostgreSQL version is `--version`) |

## Add it

```bash
beaver service create places --type postgis
```

Pin the PostgreSQL version and the PostGIS release explicitly:

```bash
beaver service create places --type postgis --version 17 --distribution-version 3.5
```

`beaver service show places` lists the two versions as separate fields.

## Use it

The `postgis` extension is already enabled — in the service's default database and in every
database you add or attach — so there is no `CREATE EXTENSION` step.

```sql
CREATE TABLE places (id serial PRIMARY KEY, name text, geom geography(Point, 4326));
INSERT INTO places (name, geom) VALUES ('Nairobi', ST_MakePoint(36.82, -1.29)), ('Mombasa', ST_MakePoint(39.66, -4.04));
CREATE INDEX ON places USING gist (geom);
SELECT name FROM places WHERE ST_DWithin(geom, ST_MakePoint(36.8, -1.3)::geography, 50000);
```

Attach it to an application exactly as you would PostgreSQL — see
[PostgreSQL](/data/services/postgresql#attach-it).

<Note>
  PostGIS Topology, Raster, and the Tiger geocoder are not enabled by default. They add
  meaningful resource use, so they are opt-in per database rather than part of every PostGIS
  service. Requesting them is currently done through the API when a database is created; the
  CLI has no flag for it yet.
</Note>

## Health

Besides checking that the database answers, Beaver runs a spatial query. A service whose
extension has stopped working reports **degraded** even while the process is up, so a running
container with a broken extension doesn't look healthy.

## Backups

`beaver service backup places` and restore work as for PostgreSQL, and spatial data and indexes
come back intact. A backup records the PostgreSQL version and PostGIS release it was taken on,
and a restore into an older PostgreSQL version, or onto a different PostGIS release, is refused
before anything is changed.

## Connect from your application

[Attach the service](/start/first-service) to your application, then redeploy so the injected variables reach the container. Your app reads the connection from the environment.

<CodeGroup>
```js Node.js
import pg from "pg";
const pool = new pg.Pool({ connectionString: process.env.DATABASE_URL });
const { rows } = await pool.query("select 1 as ok");
```
```python Python
import os, psycopg
with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
    print(conn.execute("select 1").fetchone())
```
</CodeGroup>

<Note>These snippets are illustrative; check your driver's documentation for options such as TLS and pooling.</Note>

## Verify, back up and troubleshoot

- **Healthy?** `beaver service show <name>` shows status, placement and attached applications. An unhealthy service: `beaver service retry <name>`.
- **From your laptop:** `beaver service connect <name> --local-port 5432` opens a tunnel on `127.0.0.1` ([Connect locally](/data/connect-locally)).
- **Back up:** `beaver service backup <name>` takes a manual backup; see [Backups and restore](/data/backups-and-restore) for schedules, destinations and restore.
- **Credentials:** `beaver service reveal <name>` prints the live connection string and records an audit event; rotate one database's credential with `beaver service database rotate <db-name> <service>`.
- **Detach vs delete:** detaching an app ends only its own access. `beaver service delete` keeps the data volume; `beaver service delete-volume` destroys it permanently.
