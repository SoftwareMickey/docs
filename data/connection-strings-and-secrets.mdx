A connection string contains a password. Whether the database is [hosted elsewhere](/data/bring-your-own-database) or [a container you run](/data/run-a-database-container), the
string reaches your application the same way: as an [environment variable](/deploy/environment-variables). Beaver stores and delivers the variable; it does not create, rotate or
hold a database login for you.

## Set it

<Tabs>
  <Tab title="Dashboard">Open the deployment's **Environment** tab and add `DATABASE_URL`.</Tab>
  <Tab title="CLI">
    ```bash
    beaver deploy --cloud paperclip-prod --env-file .env.production
    beaver environment vars push <container> --yes     # or import ./.env into a running container's variables
    ```
    A pushed value takes effect on the next release: `beaver container <name> redeploy`.
  </Tab>
</Tabs>

## What can read it back

Variables are [sealed](/network/sealed-secrets) on the device that sets them, for the machine that will run them, so the value is **write-only**:

- `beaver environment vars list` shows names only.
- `beaver environment vars diff` shows names only; with `--reveal` a sealed value is still shown as present, never its contents.
- The dashboard shows a sealed row as present, not its value.

Keep your own record of the connection string (a password manager or your CI secret store). If you lose it, set a new one — it cannot be recovered from Beaver.

## Rotate it

1. Create the new login or password at the database (the provider's console, or `ALTER ROLE app PASSWORD '…'` on a container you run).
2. Set the new `DATABASE_URL` with `beaver environment vars push` (or the dashboard).
3. Redeploy: `beaver container <name> redeploy`. Until you do, the running app keeps the old value.
4. Remove the old login once the new release is healthy.

## Habits

- Use a **separate login per application**, with only the privileges it needs.
- Never pass a connection string on a command line you keep in shell history; use `--env-file`.
- Do not `COPY` a `.env` into your image or commit it.
- Add `?sslmode=require` (or stronger) to any string that crosses the internet — see [TLS modes](/data/bring-your-own-database#4-require-tls).
