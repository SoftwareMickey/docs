Beaver does not back up, snapshot or restore database data. Whatever holds your data — a provider, or a volume on your machine — is what you back up, and **you** test the restore.
An untested backup is not a backup.

## Hosted database: use the provider's backups

Turn on the provider's automated backups and point-in-time recovery, note the retention period, and do a restore into a scratch database once. Also keep an off-provider
dump (below) if losing the provider account would be fatal.

## Database container: a dump on a schedule

Add a small container to the same [Compose stack](/data/run-a-database-container) that dumps the database nightly to a second named volume. Copy that volume off the
machine — a backup on the same disk dies with the disk.

```yaml
  backup:
    image: postgres:17                # same major version as db
    restart: unless-stopped
    networks: [backend]
    environment:
      PGPASSWORD: ${APP_DB_PASSWORD}
    volumes:
      - backups:/backups
    entrypoint: ["/bin/sh", "-c"]
    command:
      - |
        while true; do
          pg_dump -h db -U app -Fc app > /backups/app-$$(date +%F).dump
          find /backups -name 'app-*.dump' -mtime +14 -delete
          sleep 86400
        done
```

Add `backups:` under the top-level `volumes:`. The `-Fc` format restores with `pg_restore`. Redis already persists with `--appendonly yes`; copy the `redisdata` volume if you need an offsite copy.

## Restore

```bash
# into a fresh database (here: a container named db)
docker exec -i <db-container> createdb -U app app_restored
docker exec -i <db-container> pg_restore -U app -d app_restored < app-2026-10-16.dump
```

Restore into a **new** database name first, check the data, then switch the application's `DATABASE_URL` to it ([rotate](/data/connection-strings-and-secrets#rotate-it)). The same
dump moves a database to a new major version: restore it into a container running the newer image on a fresh volume.

## Volume snapshots

Stopping the database container and copying its volume gives a consistent file-level copy; copying a running Postgres volume does not. Prefer dumps unless the
database is large enough that restore time matters.
