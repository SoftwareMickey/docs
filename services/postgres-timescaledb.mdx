TimescaleDB is a [PostgreSQL](/services/postgresql) flavor for time-series data: the same
managed database, backups, credentials, and attach workflow, with hypertables, continuous
aggregates, and compression available.

## Add it

```bash
beaver service create metrics --type timescaledb
```

Pin the PostgreSQL version and the TimescaleDB release explicitly:

```bash
beaver service create metrics --type timescaledb --version 17 --distribution-version 2.30.1
```

`beaver service show metrics` lists the two versions as separate fields. A TimescaleDB service
starts with more storage (40 GB) than plain PostgreSQL, since time-series data tends to grow
quickly.

## Use it

TimescaleDB is already loaded and enabled — in the service's default database and in every
database you add or attach — so there is no `CREATE EXTENSION` step.

```sql
CREATE TABLE conditions (time timestamptz NOT NULL, device text, temperature double precision);
SELECT create_hypertable('conditions', 'time');
INSERT INTO conditions VALUES (now(), 'sensor-1', 21.5), (now(), 'sensor-1', 22.5);
SELECT avg(temperature) FROM (SELECT time_bucket('1 hour', time) AS hour, temperature FROM conditions) t;
ALTER TABLE conditions SET (timescaledb.compress, timescaledb.compress_segmentby = 'device');
```

Attach it to an application exactly as you would PostgreSQL — see
[PostgreSQL](/services/postgresql#attach-it).

## Tuning

Write-heavy ingestion is limited by WAL size, so `max_wal_size` is exposed as a setting
(64 MB to 16 GB):

```bash
beaver service config set metrics max_wal_size=4GB
```

Changing a setting redeploys the service.

## Health and overview

Besides checking that the database answers, Beaver creates and queries a hypertable. A service
whose extension has stopped working reports **degraded** even while the process is up, so a
running container with a broken extension doesn't look healthy. The service overview also reports how many hypertables and chunks your databases hold, how many chunks are
compressed, and the compression ratio, so you can see them without opening a SQL session.

## Backups

`beaver service backup metrics` and restore work as for PostgreSQL. Beaver handles the
TimescaleDB steps a restore needs, so hypertables — including compressed chunks — come back
intact. A backup records the PostgreSQL version and TimescaleDB release it was taken on, and a
restore into an older PostgreSQL version, or onto a different TimescaleDB release, is refused
before anything is changed.
