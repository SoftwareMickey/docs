pgvector is a [PostgreSQL](/services/postgresql) flavor: the same managed database, backups,
credentials, and attach workflow, with the `vector` column type and similarity operators
already available. Use it to keep embeddings next to your relational data instead of running a
second database.

## Add it

```bash
beaver service create embeddings --type pgvector
```

Pin the PostgreSQL version and the pgvector release explicitly:

```bash
beaver service create embeddings --type pgvector --version 17 --distribution-version 0.8.6
```

`beaver service show embeddings` lists the two versions as separate fields.

## Use it

The `vector` extension is already enabled — in the service's default database and in every
database you add or attach — so there is no `CREATE EXTENSION` step.

```sql
CREATE TABLE items (id bigserial PRIMARY KEY, embedding vector(3));
INSERT INTO items (embedding) VALUES ('[1,2,3]'), ('[4,5,6]'), ('[7,8,9]');
CREATE INDEX ON items USING hnsw (embedding vector_l2_ops);
SELECT id FROM items ORDER BY embedding <-> '[3,1,2]' LIMIT 1;
```

Attach it to an application exactly as you would PostgreSQL — see
[PostgreSQL](/services/postgresql#attach-it).

## Tuning

Index builds are limited by `maintenance_work_mem`, so it is exposed as a setting (64 MB to
4 GB):

```bash
beaver service config set embeddings maintenance_work_mem=1GB
```

Changing a setting redeploys the service.

## Health

Besides checking that the database answers, Beaver runs a nearest-neighbour query against the
`vector` type. A service whose extension has stopped working reports **degraded** even while
the process is up, so a running container with a broken extension doesn't look healthy.

## Backups

`beaver service backup embeddings` and restore work as for PostgreSQL. A restored database
keeps its vectors and indexes. A backup records the PostgreSQL version and pgvector release it
was taken on, and a restore into an older PostgreSQL version, or onto a different pgvector
release, is refused before anything is changed.
