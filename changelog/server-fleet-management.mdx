`beaver connect` now inspects a machine before asking what you want to do with it — OS, architecture, Git, Docker, available resources, and what kind of machine it even is (laptop, cloud VPS, bare metal, or CI runner). Based on that, it only offers the roles the machine actually qualifies for: **Builder**, **Host**, or **Builder + Host**. A laptop can build all day, but `connect` won't quietly let it become a production host without an explicit heads-up first.

Once enrolled, a new `server` command manages your fleet without ever touching the machines themselves:

| Command | Description |
| --- | --- |
| `connect` | Inspect this machine and register it with a qualified role. |
| `server --list` | List every server enrolled in your workspace. |
| `server update` | Change a server's name, role, or labels. |
| `server rename` | Rename a server (shorthand for `update --name`). |
| `server remove` | Remove a server from your workspace. |
| `update` | Update the CLI itself to the latest release. |

Running `server update` or `server remove` without a machine ID now opens an interactive picker — arrow keys to move, type to filter, Enter to confirm — instead of requiring you to have the ID memorized. `update` also accepts `--labels` for free-form key/value tags like `environment=production`, handy once a fleet grows past a handful of machines.

And the CLI can now update itself: `beaver update` checks the latest release, verifies it, and replaces itself in place.
