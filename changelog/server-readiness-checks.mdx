Connecting a server used to mean trusting that it was ready. Now Beaver actually verifies it — confirming the server is reachable, Docker and Git are working, it can reach your repository, and it genuinely qualifies for the role you gave it.

The check is real, not assumed: the server itself always makes the final call on whether it's equipped for the work. It never simply takes Beaver's word for it, and it won't attempt something it isn't actually ready for, even if asked.

This is what stands between a server being merely *connected* and a server actually being *deployable* — and it's what the rest of Beaver's build and deploy tooling now checks before relying on a server for anything.
