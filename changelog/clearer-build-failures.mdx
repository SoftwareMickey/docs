Not every build failure means the same thing — a missing Dockerfile, a branch that doesn't exist, and a registry rejecting a push are all very different problems. Beaver now tells them apart.

When a build fails, you get a specific, actionable reason instead of one generic "build failed" message. Beaver also now distinguishes failures worth retrying automatically — a temporary network hiccup, for example — from ones that won't resolve themselves without a change on your end, so retries happen where they'll actually help instead of leaving you guessing what to fix.
