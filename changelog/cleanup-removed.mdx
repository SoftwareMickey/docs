`beaver machine cleanup-plan` and `beaver machine cleanup` used to scan a machine's Docker state and offer to remove containers, images, networks and volumes Beaver had no record of. On a machine
you also run your own workloads on, that is exactly backwards: Beaver cannot tell your own stopped container from one it can safely reclaim, and the two mistakes do not cost the same — a stray
container wastes a little disk, a force-removed one does not come back. Both commands now only print a notice.

## What Beaver still removes

Beaver only ever removes a container, volume or network it deployed itself: a redeploy replacing its own container, an explicit delete, a scale-down retiring its own replica, a deleted Compose
stack tearing down its own networks and volumes. None of that depended on the removed scan, and none of it changes.

## What to do instead

- **See what's using space** — `beaver machine docker <id>` still reports every container, image and volume on a machine, read-only.
- **Reclaim it yourself** — `docker image prune` / `docker builder prune` on the machine directly, for dangling images and the build cache.
